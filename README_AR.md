# FAREED DEVICE LOCK — Android V1

## ما الذي يقدمه؟
تطبيق Android أولي يفعّل Lock Task Mode فقط إذا كان التطبيق مسجلاً Device Owner على الجهاز. عندها يضيف نفسه إلى قائمة التطبيقات المسموح بها ويبدأ وضع Kiosk.

## المتطلبات
- Android Studio حديث.
- Android SDK 35 (يمكن تثبيته من SDK Manager).
- جهاز Android تجريبي تملكه، مع USB debugging عند استخدام ADB.
- للتسجيل كـ Device Owner، يجب أن يكون الجهاز في حالة provisioning مؤهلة؛ غالبًا جهاز جديد أو بعد إعادة ضبط المصنع، ولا توجد حسابات/إدارة سابقة تمنع العملية. لا تعِد ضبط جهازك الأساسي قبل نسخ بياناتك احتياطيًا.

## فتح وبناء المشروع
1. فك ضغط المشروع.
2. Android Studio > Open واختر مجلد `FAREED_DEVICE_LOCK_ANDROID`.
3. انتظر Gradle Sync.
4. شغّل التطبيق على جهاز تجريبي أو Emulator.

قبل تسجيل Device Owner، ستعمل الواجهة وتعرض أن Device Owner = لا، ولن تفرض قفلًا.

## إعداد Device Owner (اختياري وعلى جهاز تجريبي فقط)
بعد تثبيت التطبيق، ومع تحقق شروط Android للتجهيز، نفّذ من Terminal:
```bash
adb shell dpm set-device-owner com.fareed.devicelock/.admin.KioskAdminReceiver
```
إذا رفض Android الأمر، اقرأ رسالة الخطأ ولا تحاول تجاوزها؛ الجهاز قد لا يكون مؤهلاً أو قد توجد حسابات/سياسة إدارة قائمة.

بعد نجاح التسجيل:
1. افتح التطبيق.
2. اضغط «إعداد وبدء وضع Kiosk».
3. لاختبار الخروج من التطبيق استخدم زر المسؤول داخل الواجهة والرمز التجريبي `1212`.

## تحذيرات مهمة
- الرمز `1212` تجريبي فقط وليس حماية إنتاجية. لا توزّع التطبيق قبل بناء مصادقة مسؤول آمنة.
- لا تستخدم Device Owner على جهاز لا تملكه أو لا تديره بتصريح واضح.
- لا توجد آلية سرية أو غير قابلة للإزالة هنا. احتفظ بمسار استعادة موثق.
- إزالة Device Owner ليست مثل حذف تطبيق عادي، وقد تتطلب إزالة الإدارة أو إعادة ضبط المصنع بحسب حالة الجهاز. اختبر على جهاز غير أساسي.
- هذا الإصدار لا يعطّل مكالمات الطوارئ أو مفاتيح الطاقة أو وسائل السلامة.


## بناء APK دون تثبيت Android Studio على الكمبيوتر
أضفنا GitHub Actions لبناء APK على خوادم GitHub:
1. أنشئ مستودعًا جديدًا على GitHub.
2. ارفع محتويات هذا المجلد كاملة إلى المستودع (بما فيها مجلد `.github`).
3. افتح تبويب Actions في المستودع.
4. اختر `Build Android APK` ثم `Run workflow` إذا لم يبدأ البناء تلقائيًا.
5. بعد نجاح البناء افتح نتيجة التشغيل (workflow run)، ثم نزّل Artifact باسم `FAREED-DEVICE-LOCK-debug-apk`.
6. فك ضغط الـ Artifact؛ ستجد `app-debug.apk`، وانقله إلى هاتف Android وثبّته.

هذا APK تجريبي Debug وليس إصدارًا نهائيًا موقّعًا للنشر العام. يحتاج المستخدم إلى السماح بالتثبيت من هذا المصدر. بناء APK لا يمنح التطبيق Device Owner تلقائيًا؛ إعداد Device Owner يظل إجراءً إداريًا منفصلًا على جهاز اختبار مملوك لك.
